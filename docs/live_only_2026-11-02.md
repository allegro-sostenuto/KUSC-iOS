# Live-only playback — 2 November 2026

Both the iPhone and Android apps now offer live playback only. Delayed listening,
rewind history, scrubbing, programme-row seeking and Resume Where Paused are
removed until a server is acquired and a server-backed design is implemented and
tested. No server, recorder, relay or deployment is part of this update.

Pause still silences the current audio. Play after a pause reconnects or rejoins
the live stream; it does not resume the old listening position. Live remains a
manual way to rejoin the live stream. Existing sleep timers, scheduled starts,
their one-minute fade, artwork/metadata, programme information, output choices,
widgets and pure-black appearance retain their existing behavior.

## Code and migration

- iPhone settings ignore old retention/resume fields when decoding and omit them
  when saved. Autoplay, appearance, minimalist mode, sleep defaults and scheduling
  defaults are preserved. The coordinator always starts with zero retention and
  never handles a historical seek. The audio engine independently clamps retention
  to zero. Legacy renderer/retention regression code remains in the source; only
  explicit DEBUG test helpers can exercise it. Normal Debug and Release launches
  cannot enable it through preferences.
- Android removes the old preference keys and returns live-only values even if
  an old caller writes them again. The rewind slider, history settings and
  programme long-press actions are removed. The service always joins fresh live
  audio and ignores obsolete seek requests. `LiveStreamBuffer` keeps a fixed,
  bounded HLS transport window instead of a configurable rolling archive.
- Ordinary decoder/network buffering and broadcast latency still exist. Neither
  app promises zero-latency audio, offline listening or continuity through an
  arbitrary network outage. Transport files are not user-accessible rewind history.
- Historical specifications, audits and server planning notes remain reference
  material. This scope overrides their old descriptions of available rewind
  controls. Future server work needs a new implementation and validation pass.

## Validation and device checklist

Automated coverage includes legacy preference migration, rejected positive iPhone
retention requests, stale seek actions, live-only settings/layouts, live resume,
Pause winning over pending joins, and existing scheduling/fade tests. Build and
runtime results will be recorded after the checks complete.

For an installed update, verify:

1. Upgrade from nonzero retention with Resume Where Paused enabled. The options
   and slider disappear while unrelated settings and saved starts remain.
2. Pause longer than the former history window, then Play. Audio joins live;
   artwork and programme details follow the audible broadcast.
3. Tap and hold previous programme rows. Neither action seeks or starts playback.
4. Check Pause/Play and Live in the app and supported system surfaces. Pause during
   a pending connection must still win. Refresh and swiping must remain usable.
5. Run sleep and scheduled-start checks, including the full one-minute fade,
   manual pause, deletion, output policy and battery protection.

Physical Bluetooth/AirPlay, Samsung background restrictions and unattended
scheduled playback still require the relevant phone checks.
