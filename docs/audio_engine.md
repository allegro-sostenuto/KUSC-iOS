# Audio acquisition, buffering and clock mapping

The selected source is KUSC's 96 kbit/s HE-AAC HLS stream, discovered through its official web player. Both modes receive the same configured `.m3u8` endpoint. The live media playlist observed on 19 September 2026 contained unencrypted `.aac` segments, `EXT-X-MEDIA-SEQUENCE`, `EXT-X-TARGETDURATION:10` and `EXT-X-PROGRAM-DATE-TIME`. Observed segments lasted roughly 4–10 seconds.

## Zero-minute retention

`AVPlayer` loads the remote HLS stream directly. The app creates no audio-buffer directory or capture files in this mode. Apple's player can maintain its own minimal streaming cache. Pausing sets `canUseNetworkResourcesForLiveStreamingWhilePaused = false`; resuming replaces the item to join live instead of deliberately exposing old playback history. `AVPlayerItem.currentDate()` supplies the timestamp currently being heard when the HLS clock is available.

## One to fifteen minutes

`HLSIngestor` resolves the highest-bandwidth variant, retains the resolved media-session URL, polls at one quarter of target duration (0.5–2 seconds), and downloads each new media sequence once. Time already spent downloading and acknowledging a batch counts toward that poll interval, so a slow batch immediately refreshes its manifest. These downloaded AAC files serve both playback and history. There is no second remote player receiving another copy of the audio. Startup fetches the newest two segments and waits for both before a single live join; it no longer plays the first and rebuilds the queue on the second arrival. History accumulates while the app runs.

Each segment is checked for complete ADTS frames. The HLS program date plus preceding `EXTINF` durations determines its absolute start. On playlist reload, verified overlapping segments preserve the established date mapping if the old date tag slides out of the window. The parser checks sequence, resolved URI, duration and discontinuity epoch within the same playlist connection; it does not bridge missing overlap or invent a clock for a new session. Buffered playback feeds compressed AAC packets into one `AVSampleBufferAudioRenderer` with one `AVSampleBufferRenderSynchronizer`. `AudioFileReadPacketData` reads the local compressed data with explicit packet sizes. Core Media buffers preserve the file format, magic cookie, packet payloads and encoded timing; ordinary file boundaries append packets without flushing or replacing the decoder. HTTP errors, malformed/unsupported manifests, non-AAC segments, backward clock resets and dates that cannot be resolved from a valid anchor fail visibly through the coordinator's reconnect policy. The app does not substitute a guessed receipt timestamp for a missing HLS clock in buffered mode.

The safe live target is separate from the latest downloaded end and latest advertised end. Live and right-edge seeks use the same target: downloaded headroom equal to the longer of the latest two segment durations plus four seconds for polling/downloads (minimum eight seconds, maximum 64), restricted to the newest continuous suffix. Typical ten-second files therefore join fourteen seconds behind the downloaded end, in the preceding file. The target advances on a monotonic clock instead of jumping on every segment arrival, with a two-second headroom floor. If acquisition recovery exposes more than the join headroom plus one observed segment (capped at 128 seconds), the live definition reanchors to a fresh join target; a delayed listener's actual cursor is not changed. Short suffixes use only available audio. These explicit bounded values are a provisional continuity policy, **not measured device latency guarantees**. HLS is not zero-latency broadcasting. Station-supplied program dates synchronize the transport; any discrepancy between the station's playlist metadata and its actual broadcast remains upstream timing uncertainty.

Only confirmed media time updates the heard cursor. A gap seek resolves to the next retained segment; its requested/pending target remains separate until the transport is ready at that position. Each seek has a generation; pause, later seeks and teardown invalidate obsolete completions. Encoded sample durations determine contiguous renderer timestamps, and the corresponding segment maps those times to the station timeline. Starvation preserves the last consumed endpoint rather than replaying the newest segment start. The engine never substitutes wall-clock time for an unavailable direct-HLS media timestamp. Snapshots expose playing, waiting, seeking and timing confidence separately from playback intent.

Refill uses already downloaded successors without waiting for another HLS arrival. Successors follow retained segment identity/order; the small timestamp overlaps accepted by acquisition do not authorize dropping an entire file. Explicit seeks, genuine discontinuities and output-route flush recovery can reset the renderer; ordinary arrivals and pause/resume preserve it. A pending zero/positive-retention replacement owns its Live action, so the outgoing buffered transport cannot start a second remote HLS player while its mode is changing.

Seek preparation selects complete compressed packets overlapping the one-second interval before the target, including a preceding file's tail when necessary. Reading an entire preceding file into a paused renderer can fill its internal queue before the target is reached. Even bounded preroll can fill the paused output queue at an exact file boundary unless its decoded output is discarded. Seek-only sample-buffer copies therefore use `kCMSampleBufferAttachmentKey_TrimDurationAtStart` to decode the preroll for context while discarding output before the requested time. Encoded packet bytes, timestamps and format remain unchanged. Ordinary sequential playback still supplies every packet without trim attachments. File-end metadata does not become a decoder reset at storage boundaries.

The slider observes a separate four-Hz `PlaybackTransportClock`. It may interpolate the heard position for at most 0.3 seconds after a verified advancing sample, and freezes that position during pause, waiting or seeking. Only an active drag freezes its coordinate mapping; the history label always follows the latest acquired window, including during a drag or pause. Non-touch adjustments commit without leaving a frozen preview. Artwork, metadata and system surfaces use the slower engine snapshots. The clock also exposes real playable intervals so missing media can be indicated. The live label is withheld when acquisition is stale (download age greater than 1.5 target durations/12 seconds, or advertised backlog greater than a target duration/two seconds).

HLS discontinuities are retained explicitly. A newly encountered discontinuity requires a program-date-time anchor; either ordering of those two tags before the segment URI preserves an explicit anchor. A known segment's mapping can be recovered from verified overlap in the same discontinuity epoch, but an unknown discontinuity is never bridged by adding the preceding duration. Missing or backward timestamps fail through the reconnect policy instead of inventing a timeline. Forward media gaps remain visible and resolve to the next retained interval.

## Retention and resource limits

- The valid cursor begins at the later of the first available segment and `newest acquired audio end - selected minutes`.
- A segment crossing that cutoff remains on disk until its remaining suffix expires, but seeking to its expired prefix is forbidden.
- If playing audio ages out, playback jumps to the oldest valid cursor before continuing. Paused playback cannot resume expired audio: resume clamps to the oldest retained point.
- Whole expired files are deleted on each segment arrival or retention change. The store also has hard limits of 512 segments and 64 MiB. At the observed rate, fifteen minutes is approximately 10.8 MB of compressed audio, plus at most one straddling segment and ordinary player/network buffers.
- Responses have hard in-memory limits: 1 MiB for a playlist and 2 MiB for an AAC segment. File protection permits reads after first unlock while the screen is locked. Files are excluded from backup.
- Pausing with retention enabled leaves the single ingestor running while iOS permits execution. This does not create a background-execution guarantee for a paused app. A suspended connection is revalidated/reconnected on resume.
- Stop cancels ingestion, invalidates stale callbacks, releases player items and deletes the run directory. Initialization removes crash leftovers. No delayed cursor survives process termination.
- Switching between zero and positive retention closes the old acquisition path and joins live through the new path. Changing between positive durations preserves the connection and trims immediately.

## Validation status

The September 20 update includes pure Swift regression cases for matching live/right-edge targets, segment-arrival stability, starvation/recovery, gap resolution, actual cursor retention, stale-live classification, all retention settings and poll timing. These cases do not exercise AVFoundation itself. The queue-refill, timestamp-overlap and mode-switch follow-up at `9782f2a` passed all 75 portable tests and both ordinary Release device builds (`KUSC-SE` and `KUSC-17`, including the extension) under Xcode 26.6 in [GitHub Actions run 35510690436](https://github.com/allegro-sostenuto/KUSC-iOS/actions/runs/35510690436). All 86 hosted tests also passed on the iPhone 17 and SE simulator profiles: the 75 portable cases, seven native engine state/queue tests and four model/gain-boundary tests. The native tests exercise AVFoundation-backed objects and model boundaries, but do not record audible output. That run's overall failure was in landscape screenshot assertions, not the audio tests. Later layout/capture results are recorded in `update_2026-09-20.md`.

The local Windows editing host has no Xcode/iOS SDK or checked Windows/Ubuntu Swift compiler; it provides syntax, structure and icon checks. CI supplies the SDK compilation and portable XCTest evidence above. Neither environment establishes physical output continuity or long-run audio backlog measurements.

For device diagnosis, ordinary Release builds offer **Settings → Playback Diagnostics**. Capture is disabled by default and started explicitly; the first failure freezes the bounded report before teardown, and the user can copy/share it from Settings. Debug builds additionally support `-KUSCAudioDiagnostics` console traces. Events record monotonic time/generation, seek generations, manifest/downloaded sequence, encoded-minus-manifest duration, advertised/downloaded/safe-live/oldest/heard positions, queued media, playback/seek/stale state, gain and sanitized errors. The existing duration tolerance (0.2 seconds or 1%) remains a validation ceiling, not permission to assume drift-free audio: encoded media time maps the cursor within each segment, and duration deltas need a long-run captured trace. The [September 21 device report](buffer_clock_fix_2026-09-21.md) identifies loss of the program-date mapping on a sliding playlist refresh. The owner confirms build 9 continues playing after that correction, but reports periodic dips at both Live and delayed positions. The [continuous-renderer follow-up](buffer_continuity_followup_2026-09-21.md) addresses the separate per-file decoding boundaries and frozen history label.

Parser tests cover split AAC headers/frames, HE-AAC core-rate duration, ICY framing, HLS master selection, propagated program dates, malformed playlists and unsupported formats. Retention, gap-aware seeking and pause policies have separate pure Swift tests. Official endpoint responses and their HLS structure were inspected during implementation.

A fresh real-stream segment fetched at 2026-09-19 17:11 UTC contained 122,831 bytes: 1,357 bytes of ID3/header material followed by 215 complete ADTS frames, with no trailing partial frame. ADTS duration was 9.984580498866 seconds; HLS `EXTINF` was 9.98458 seconds, a difference below one microsecond. The 22,050 Hz core rate and decoded 44,100 Hz stereo HE-AAC reported by `ffprobe` confirm correct SBR duration handling. A separate fresh-request timing measurement observed 15.68 seconds to the HLS master through redirects and 7.55 seconds to its media playlist. These are environment/network observations, not a station latency guarantee. The engine permits 45 seconds for initial playback and 12 seconds for a stall after playback has begun; the coordinator applies its separate one-minute reconnect deadline.

CI compiles and exercises native media objects, but physical iPhone audio outputs remain unavailable in this session. Continuity across AAC boundaries, AirPlay behavior, exact seek precision and multi-hour playback require the device tests in `manual_test_plan.md`. The continuous renderer eliminates the former per-file player handoff; uninterrupted physical output is not established by a simulator result. The implementation intentionally rejects encryption, byte-range segments and fragmented MP4 if the station changes its current format.
