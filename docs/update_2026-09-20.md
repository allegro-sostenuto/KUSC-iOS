## Lag hypotheses

- **LAG-01:** Separate AAC `AVQueuePlayer` items remain. Source-level startup/underrun risks were changed; a device recording is still needed to establish whether decoder joins cause the reported pauses. Gapless output is not verified. Replace this path if recorded joins still stall after the corrected headroom/startup changes.
- **LAG-02:** Poll timing includes download/acknowledgement work instead of adding up to five more seconds. Advertised/downloaded edges and diagnostic timings are distinct. Sustained slow-network backlog remains unmeasured.
- **LAG-03:** Acquisition age/backlog prevents stale local files being labeled live. Ordinary source latency and deliberate rewind remain separate.
- **LAG-04:** Startup waits for the initial segment pair and joins once. The previous first-play/second-arrival queue rebuild was source-confirmed; its audible severity was not recorded on hardware.
- **LAG-05:** Discontinuities, actual ADTS durations and manifest timing remain explicit. Long-run duration drift, codec changes and decoder priming are unmeasured.
- **LAG-06:** Metadata publishes only changed content; progress has its own observer; Live Activity JPEG thumbnails are cached by image identity. CPU/memory/energy improvements are not measured.
